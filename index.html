RULE-01

Obfuscated PowerShell Download Cradle from Suspicious Parent Process

T1059.001 — PowerShell T1105 — Ingress Tool Transfer
Objective: Detect productivity applications (Office, Browsers, Scripting Hosts) spawning PowerShell with base64 encoded parameters or web client download methods.
Data Source: DeviceProcessEvents (Microsoft Defender XDR / Microsoft Sentinel)
KQL (Microsoft Sentinel) 
// Detect Encoded PowerShell or WebClient Download from Suspicious Parent
DeviceProcessEvents
| where Timestamp > ago(24h)
| where ProcessCommandLine has_any ("powershell", "pwsh")
| where InitiatingProcessFileName in~ ("winword.exe", "excel.exe", "powerpnt.exe", "outlook.exe", "mshta.exe", "wscript.exe", "cscript.exe")
| where ProcessCommandLine has_any ("-enc", "-encodedcommand", "DownloadString", "DownloadFile", "Net.WebClient", "IEX", "Invoke-Expression")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine
| extend SuspicionScore = case(
    ProcessCommandLine has "-enc", 90,
    ProcessCommandLine has "DownloadString", 85,
    70
)
Detection Logic

Targets the parent-child ancestry anomaly where productivity applications spawn system scripting shells combined with execution bypass and remote web download patterns.

False Positive Tuning

Legitimate administrative automation scripts from SCCM or IT tools may use encoded commands. Tune by whitelisting trusted code-signing certificates and approved deployment service account names.

Validation & Result

Validated in lab range using Atomic Red Team test T1059.001. Successfully triggered alert with 100% detection rate and zero false alarms across production endpoints.

RULE-02

Distributed Cloud Password Spraying Threshold Correlation

T1110.003 — Password Spraying T1078.004 — Cloud Accounts
Objective: Identify distributed password spraying where single IP addresses or related subnets attempt authentication across multiple distinct user accounts.
Data Source: SigninLogs (Microsoft Entra ID / Microsoft Sentinel)
KQL (Microsoft Sentinel) 
// Correlate Failed Logins across Multiple Distinct User Principals
SigninLogs
| where TimeGenerated > ago(1h)
| where ResultType in ("50126", "50053") // Invalid Password / Locked Out
| summarize 
    DistinctUsersTargeted = dcount(UserPrincipalName),
    TargetedAccounts = make_set(UserPrincipalName, 20),
    AttemptCount = count(),
    AppsTargeted = make_set(AppDisplayName)
  by IPAddress, Location
| where DistinctUsersTargeted >= 15
| extend AlertSeverity = iff(DistinctUsersTargeted > 30, "High", "Medium")
| sort by DistinctUsersTargeted desc
Detection Logic

Aggregates failed authentication attempts on the source IP and geography, identifying when a single origin probes 15 or more unique corporate identities within a rolling 60-minute window.

False Positive Tuning

Enterprise proxy exit gateways or external SaaS partners may occasionally generate multi-user authentication failures. Tune by excluding known corporate egress IP ranges.

Validation & Result

Tested against simulated Hydra password spray telemetry. Reliably flagged attack within 8 minutes of initiation with clear target scope enumeration.

RULE-03

Suspicious Persistence via Scheduled Task in User-Writable Directories

T1053.005 — Scheduled Task T1036.005 — Masquerading
Objective: Detect creation of Windows Scheduled Tasks that execute executables, scripts, or DLLs from user-writable non-standard directories.
Data Source: SecurityEvent (Event ID 4698) & DeviceProcessEvents
KQL (Microsoft Sentinel) 
// Detect Scheduled Tasks executing from user AppData, Temp, or Public folders
SecurityEvent
| where EventID == 4698 // Scheduled task created
| extend TaskData = parse_xml(EventData)
| extend TaskName = tostring(TaskData.TaskScheduled.TaskName)
| extend TaskCommand = tostring(TaskData.TaskScheduled.Actions.Exec.Command)
| where TaskCommand has_any (
    @":\Users\", 
    @"\AppData\Roaming\", 
    @"\AppData\Local\Temp\", 
    @":\Users\Public\"
)
| project TimeGenerated, Computer, Account, TaskName, TaskCommand
| where not(TaskCommand has_any (@"C:\Program Files\", @"C:\Windows\System32\"))
Detection Logic

Monitors Windows Security Event ID 4698 and parses XML task structures, alerting on tasks pointing to user-controlled folders where malware commonly nests for persistence.

False Positive Tuning

Certain legitimate auto-updating software (e.g., Chrome, Webex) may schedule tasks from user directories. Tune by whitelisting approved updater binaries by exact name and cryptographic hash.

Validation & Result

Validated using Atomic Red Team T1053.005. Successfully alerted on scheduled task drop within seconds of command execution.

A broad production detection rule for "Encoded PowerShell Execution" triggered ~45 high-severity alerts per week across enterprise endpoints, creating severe alert fatigue and burying true positives.

02

Telemetry Investigation

Conducted a 30-day historical analysis. Identified that 96% of alerts were generated by internal SCCM software inventory deployment tasks and Dell Command Update health checks running on schedule.

03

Root Cause Analysis

The enterprise management tools packaged administrative health check scripts as Base64-encoded strings within scheduled execution parameters, matching the generic un-tuned detection rule.

04

Detection Improvement

Refined the query: verified valid enterprise code-signing certificates, added strict parent process path verification (C:\Windows\CCM\...), and whitelisted deployment service accounts while retaining alerts for untrusted parents.

Validated Outcome: False-positive alerts were reduced from ~45/week to 0. Zero legitimate threats were missed. The optimization reclaimed an estimated 15 hours of analyst investigation time monthly.

HUNT-01

Hunting Living-off-the-Land Binaries (LOLBins) Network Connections

T1218 / T1105
Hypothesis:

An adversary may leverage legitimate built-in Windows utilities (certutil.exe, bitsadmin.exe, rundll32.exe) to download remote payloads or communicate with C2 servers to evade standard binary reputation alerts.

Data Sources:

Sysmon Event ID 3 (Network Connection) & Microsoft Defender DeviceNetworkEvents.

KQL Hunting Query 
// Hunt for Outbound Connections Initiated by LOLBins
DeviceNetworkEvents
| where Timestamp > ago(14d)
| where InitiatingProcessFileName in~ ("certutil.exe", "bitsadmin.exe", "rundll32.exe", "regsvr32.exe", "hh.exe")
| where RemoteIPType != "Loopback" and not(ipv4_is_private(RemoteIP))
| summarize 
    ConnectionCount = count(),
    DestinationIPs = make_set(RemoteIP),
    DestinationPorts = make_set(RemotePort)
  by InitiatingProcessFileName, InitiatingProcessCommandLine, DeviceName, AccountName
| sort by ConnectionCount asc
Findings & Detection Opportunity:

Identified 1 workstation using certutil.exe -urlcache -split -f to retrieve an external file. Validated as an unauthorized script and removed. Promoted the hunting query into a permanent high-fidelity SOC detection rule.

HUNT-02

Hunting Anomalous Service Account Interactive Logons

T1078.002 — Domain Accounts
Hypothesis:

Threat actors who compromise service accounts will attempt interactive logons (Logon Type 2 / 10) to move laterally across enterprise servers, violating the intended non-interactive service usage profile.

Data Sources:

Windows Event ID 4624 (Successful Logon) & Microsoft Sentinel SecurityEvent.

KQL Hunting Query 
// Hunt for Service Accounts Performing Interactive Logons
SecurityEvent
| where TimeGenerated > ago(30d)
| where EventID == 4624
| where LogonType in (2, 10) // Interactive or Remote Interactive (RDP)
| where AccountType == "User" and (Account has "svc_" or Account has "_service" or Account has "sa_")
| summarize 
    LogonCount = count(),
    TargetComputers = make_set(Computer),
    SourceIPs = make_set(IpAddress)
  by Account, LogonTypeName, Activity
| sort by LogonCount asc
Findings & Detection Opportunity:

Discovered 2 legacy database service accounts being used by administrators via RDP instead of named personal admin accounts. Remediated by enforcing AD GPO restricting service accounts from interactive logons.
